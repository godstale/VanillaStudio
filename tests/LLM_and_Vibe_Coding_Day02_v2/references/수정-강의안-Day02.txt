
# 수정 강의안 (LLM 과 바이브 코딩 2일차)


# 바이브 코딩의 시작까지

## Scene - GPT 쇼크

- 2022년 11월 30일, OpenAI가 GPT-3.5 기반의 대화형 AI 서비스 ChatGPT(연구용 프리뷰 버전)를 무료로 공개했습니다.
출시 불과 5일 만에 가입자 100만 명을 돌파했고, 두 달 만인 2023년 1월에는 월간 활성 사용자(MAU) 1억 명을 넘기며 역사상 가장 빠르게 성장한 소비자 애플리케이션이 되었습니다.
- 이전의 챗봇들은 기계적인 답변을 반복하거나 문맥을 이해하지 못해 금방 티가 났지만, 챗GPT는 이전 대화를 기억하고 문맥에 맞는 유창한 문장을 구사해 사람들을 경악하게 만들었습니다.
- 구글의 '코드 레드(Code Red)' 선포: 전 세계 IT 업계는 비상에 걸렸습니다. 특히 검색 비즈니스의 왕좌에 있던 구글은 내부적으로 최고 비상사태(Code Red)를 선포하고 AI 전환을 서두르는 계기가 되었습니다.
- 한쪽에서는 "AI가 인간의 일자리를 대체할 것"이라며 두려움과 윤리적 우려(가짜 뉴스, 교육 현장의 과제 대필 등)를 제기했고, 다른 한쪽에서는 "산업 혁명에 버금가는 변화가 시작됐다"며 열광했습니다.


## Scene - 프로그래머들의 탐색

- 프로그래머들도 ChatGPT 를 코딩 업무에 활용 가능한지 탐색
  - 코드 스니펫(Code Snippet, 재사용할 수 있는 짧은 소스 코드 조각)
  - 에러 해결책 검색 대용
  - 언어 번역
  - 문서 작업, 이메일과 같은 업무 보조

하지만 물 밑으로 중요한 움직임이 있었음


## Scene - GitHub Copilot

- 2022년 6월 GitHub Copilot 정식 출시
  - 약 1년간의 프리뷰 기간을 거쳐 전 세계 모든 개발자를 대상으로 유료 서비스($10/월)로 공식 정식 출시
  - VS Code 에디터 확장 프로그램 형태
  - 오직 실시간 '코드 완성(Autocomplete)'에 극도로 특화된 도구
  - 초기 AI 코딩의 문을 연 중요한 이벤트

- AI 코딩의 시작을 이끈 3위 일체
  - VS Code 에디터 확장 프로그램 형태
    - VS Code: 2010년대 초반, 웹 개발 생태계는 JS framework 급성장으로 대변혁. 가볍고 빠르고 확장성이 좋은 에디터로 출시, 곧 대중화 됨 (2015)
    - 가장 대중적인 코드 IDE 와의 만남 (MS 제작)
  - GitHub - 학습 자료
    - 전 세계 개발자의 놀이터, 코드를 저장하고 공유하는 공간
    - MS 가 인수 (2018.06, 75억 달러(약 8조 원 규모)), AI 학습
  - OpenAI - LLM
    - MS가 대규모 투자

## Scene - 탭 코딩

- 탭 코딩: 
  - 개발자가 자연어로 주석을 작성하고 엔터를 치면, 코파일럿이 의도를 파악해 주석 바로 밑에 코드를 생성했습니다.
    - 예시: // 여기 100명의 사람 이름을 ㄱㄴㄷ 순 정렬해서 배열에 넣어줘 -> a[0] = 가철수, a[1] = 나영희... (애니메이션으로 보여주자)
  - 인라인 자동 완성 (Auto-completion & Tab 적용)
    - 함수 이름이나 매개변수(Signature)만 정의해도 함수 본문 전체(Function body)를 회색 텍스트(Ghost Text)로 자동 제안했습니다.
    - 점점 기능이 향상되면서, 서너 글자만 쳐도 자동완성이 동작
  - 반복 패턴 감지 및 자동 완성 (Boilerplate Code / Repetitive Patterns)
  - 정규표현식(Regex) 작성과 검증, SQL 쿼리 생성에 매우 강함
  - 문제가 발생하면 검색하는 시간이 축소, 집중력 유지
  - AI 페어 프로그래밍의 시작

- 탭코딩의 단점
  - 아직 LLM 은 수동적이고 함수 단위의 격리된 작업만 수행
  - 개발자의 상세 가이드가 필요. 
  - 단순 반복 업무 위주의 사용
  - 저작권 및 학습 데이터 논란
  - 환각(Hallucination) 및 버그 코드


## Scene - 커서와 코딩 에이전트

- 2023년 3월 등장 (Anysphere) -> 2023년 말~2024년 본격적 기능 확장 후 주목
- 코파일럿은 VS Code 와 같은 IDE 위에 올린 '플러그인/확장 프로그램'
- Cursor 팀은 VS Code를 포크(Fork)하여 에디터 전체를 AI 중심으로 처음부터 재설계
  - 프로젝트 전체 파일들의 구조를 파악
  - 다중 파일에 작업
  - @Files, @Folders, @Docs, @Web 등을 활용해 AI에게 원하는 파일이나 문서, 웹검색 결과를 전달
  - 수정, 빌드, 디버깅에 참여
  - 탭 코딩 뿐 아니라 Agent 와의 채팅 중심으로 작업자의 작업 전반에 참여

- 더 복잡한 작업을 수행, 개발에서의 AI 비중이 높아짐
- 불과 몇 개월 새에 "Copilot은 이제 옛날 물건이다"
- AI 는 더 자율성을 갖추게 되었다. 하지만 여전히 개발은 개발자가 주도한다.
- 훗날 커서는 2026년 6월 600억 달러(약 85조~90조 원)로 SpaceX 에 인수됨


## Scene - 클로드 코드의 등장

- 2021년 1월 | 앤트로픽 설립
  - OpenAI의 연구 부사장이었던 다리오 아모데이(Dario Amodei)와 그의 동생 다니엘라 아모데이(Daniela Amodei)를 비롯해, AI 안전성(Safety)과 정렬(Alignment) 문제에 중점을 둔 핵심 연구진 7명
- 2023년 7월 | 클로드 2 (Claude 2) 및 웹 서비스(claude.ai) 론칭
- 2024년 6월 Claude 3.5 Sonnet 등장하면서 코딩 성능이 크게 향상
- 2024년 10월 | Claude Desktop (데스크탑 앱) 출시
  - LLM 이 웹을 벗어나 PC 로 이식됨. 로컬 파일, 프로그램과 결합
- 2024년 11월 25일 MCP(Model Context Protocol)를 발표
  - 외부 도구에 연결되는 표준 확립
- 2025년 2월 안드레 카파시가 X에 올린 글에서 바이브(Vibe) 코딩을 언급
- 2025년 5월 22일 Claude Code 정식 출시
  - 자율형 코딩 에이전트 중심의 설계, 바이브 코딩 트렌드 선도
- 이후 Gemini CLI, Codex CLI, OpenCode 등등 폭발적인 확산


# 바이브 코딩 진화사 - 01. LLM 을 에이전트로

## Scene - 걸음마

- ChatGPT 의 시작은 웹에서 실행하는 챗 화면 (대화형 챗봇)
  - LLM 자체만으로는 답변 머신에 불과
- 프롬프트 엔지니어링의 시대
  - 최면을 걸듯 LLM에게 자아를 설정
  - 어떻게 얘기하면 내가 원하는 답을 더 잘 얻을 수 있을까
  - LLM 이 이해하기 쉬운 형태의 프롬프트는 무엇일까
  - 프롬프트 엔지니어가 주목

- LLM 과 기억
  - 세션(한 화면에서 대화 맥락이 유지되는 상태)동안 LLM은 대화 내역을 기억
  - 하지만 기본적으로 LLM 은 학습된 정보 외에는 알지 못한다. 
  - LLM 은 학습 시점의 시간에 고정되어 버린 지능
  - 대화 내역을 기억하는 것은 내가 던진 프롬프트 앞에 챗 기록을 덧붙여 보내기 때문 (System prompt 영역)
  - 대화가 길어질수록 앞의 기억은 흐려지고, 오동작을 하기 시작

- 학습된 정보와 채팅창을 넘어 LLM 이 외부 세계와 소통하면서 더 복잡한 작업을 처리할 수 없을까?
  

## Scene - 도구를 쥔 AI

- LLM의 능력은 학습 데이터에 한정
  - 학습을 마치고 외부 세계로 나오는 순간, 현재 시간도 알지 못함

- 2023 ReAct(Reasoning and Acting) 논문
  - 언어모델에게 도구를 이용한 문제 해결 방법을 알려주는 획기적 아이디어
  - 도구를 사용한다는 것은
    - 언어모델은 자신이 사용할 수 있는 도구들을 인식해야 합니다
    - 문제를 해결하기 위해 어떤 도구들을 사용할지 결정할 줄 알아야 합니다.
    - 여러 도구들을 사용해서 문제를 순차적으로 해결할 수 있도록 작업을 계획할 줄 알아야 합니다. (CoT)
    - 도구를 호출해서 나온 결과를 판단해서 작업을 다시 수행할지 또는 반복할지를 판단할 줄 알아야 합니다.
  - 추론(Reasoning)과 행동(Acting), 관찰(Observation)을 교차 반복
  - ReAct 에이전트 탄생 - 외부와 상호작용하는 에이전트의 시작 
  - 웹 검색, 파일 관리, 코드 실행...

- 도구에 대한 수요는 높은데 제각각 개발을 하면 LLM 연결이 어렵다. 표준화가 필요하다.


## Scene - MCP

- 2024년 11월 25일 Anthropic 에서 MCP(Model Context Protocol)를 발표
- MCP 를 이용해서 외부 서버와 PC에서 돌아가는 프로그램 등을 연결
- 대표적 MCP - GitHub/Context7/Filesystem/Playwright/Firecrawl/Supabase/PostgreSQL/Notion/Slack...

- MCP 표준이 마련되었다. 이제 MCP 와 LLM 을 붙이고 더 강력한 에이전트를 만들자


## Scene - 클로드 코드

- 더 독립적, 자율적인 에이전트에 대한 요구
  - PC의 파일과 프로그램에 대한 제어
  - 프로젝트의 데이터와 작업들을 관리할 줄 알고
  - 최신 정보를 검색 및 리서치
  - 장기기억 및 프로젝트 수행 능력
  - 사용자의 코드 단위의 가이드가 아니라 요구사항을 자율적 처리

- 이를 가장 효율적으로 구현한 코딩 에이전트 - 클로드 코드 등장
  - 코드에 강한 LLM 모델인 sonnet 사용
  - 빠르게 발전하고 텍스트 기반인 LLM 특성상 복잡한 UI 는 오히려 부담
  - 가벼운 실행 환경 (PC 요구사양이 낮음)
  - 개발자들에게 익숙한 형태인 CLI 기반
  - CLI 기반이면 원격 제어도 용이

- LLM 에 클로드 코드라는 CLI 앱을 입혀주니, 에이전트의 모습을 갖춤


# 바이브 코딩 진화사 - 02. 에이전트의 날개짓

## Scene - Plan 모드

- 손발이 생긴 초보 에이전트에게 일을 시켜보니 문제가 발생
  - "로그인 기능 넣어줘"라고 했더니 전체 설계도 안 보고 무조건 파일부터 고치다가 원래 잘 돌아가던 부분까지 고장
  - 아직 언어모델이 거대하고 복잡한 소프트웨어 작업을 처리하기엔 부족

- 거대하고 복잡한 소프트웨어 작업을 위해 무엇이 필요할까?
  - 코딩 작업을 시작하기 전에 프로젝트를 상세히 파악하고
  - 파악된 정보를 바탕으로 상세한 작업 계획을 수립
  - 불명확한 부분들은 웹 검색을 하거나 사용자에게 문의
  - 충분히 계획을 세우고 작업을 수행

- 이를 위해 Cursor, Claude Code 등은 Plan 모드를 도입
- LLM 도 여기에 맞게 추론(Reasoning, CoT)을 충분히 수행하도록 학습됨


## Scene - Thinking effort

- 현재의 에이전트들은 기본적으로 작업 시작 전 추론 과정을 수행
- 하지만 사용자의 요청을 처리하기 위해 어느 수준으로 추론을 해야할지는 의문
- 이 부분은 사용자의 몫
  - 이를 위해 사고 강도(Thinking Effort, /effort low/medium/high) 개념 도입
  - 강도가 높을 수록 여러 가설을 검토한 후 행동에 나서도록 유도
  - 복잡한 문제에 적합하지만 더 오랜 시간과 토큰 비용을 소모
- 기본적으로는 LLM 모델의 등급에 따라 추론의 성능이 결정됨
  - /model 명령어
  - 하지만 같은 모델 내에서도 추론 강도를 조절할 수 있음
- LLM 모델과 작업에 따라서 다르게 적용
  - 고급 모델(medium), 중급 모델(high)
  - 단순 작업(low)


## Scene - Skill

- 폭발적인 도구의 확장으로 MCP 생태계가 커질 무렵 문제에 봉착
  - MCP 는 LLM 이 도구를 사용할 수 있도록 상세한 매뉴얼을 제공
  - 도구가 많아지니 매뉴얼도 너무 많이짐. 매번 LLM 요청할 때마다 전송하는 것도 비효율적

- skill 생태계 등장 
  - 에이전트에게 작업 노하우와 표준 운영 절차(SOP)를 알려주는 가볍고 독립적인 마크다운 지침서
  - 도구의 간단한 설명과 언제 호출할지만 알려줌. 
  - 도구가 필요할 때 SKILL.md를 참조하여 실행.

- 현재 MCP 로 외부 프로그램/서버/서비스 연동
- 스킬이 범용적인 도구 역할을 함


## Scene - 서브 에이전트(Sub-Agent)

- 점점 복잡한 작업을 에이전트가 처리하다보니 문제가 발생
  - 기획, 리서치, 디자인, 개발, 빌드, 테스트, 출시 등 복잡 다양한 작업을 수행
  - 하나의 에이전트가 이것을 모두 담당하기에는 참조 데이터가 너무 많음
  - 에이전트와의 대화가 길어지면서 기억이 흐려지고 너무 느려짐
  - 긴 작업 후 문제가 발생하면 되돌리기도 어려움

- 서브 에이전트
  - 작업 계획에 따라 작은 작업들로 분할
  - 분할된 작업을 여러개의 서브 에이전트로 수행
  - 독립된 대화를 시작하는 효과로 더 정확하고 저렴하게 작업을 수행
  - 여러 서브 에이전트를 동원해서 병렬로 빠르게 작업 수행
  - 전체적인 작업 계획과 서브 에이전트 관리는 메인 에이전트가 수행

- 이때 프로젝트 전체의 원칙과 서브 에이전트들의 역할을 **AGENTS.md** 에 기록. 이것이 향후 표준화 됨
- Plan 모드로 작업을 분할하고, 서브 에이전트로 작업을 처리 -> 더 큰 프로젝트를 다룰 수 있게 됨
- 프롬프트 엔지니어링 -> 컨텍스트(Context) 엔지니어링으로 진화
  - "AI가 스스로 판단하도록 어떤 환경과 정보 체계를 깔아줄까?" 를 고민하는 단계


## Scene - 루프 엔지니어링

- 회사 업무 프로젝트 단위의 작업은 복잡하고 처리하는데 시간도 오래 소요됨
  - 대화가 길어지면 기억이 흐려지고 환각 급증 (context rot)
  - 사람이 항상 옆에 붙어서 모니터링 하기가 어려움
  - 작업을 요청하면 코드를 작성하고 스스로 테스트 하며, 결과를 분석해서 다시 코드를 작성하는
  - 진정한 자율 코딩이 가능할까?

- 이 문제를 해결하기 위한 방법론이 자율 루프(Ralph Loop)
  - 개발자 제프리 헌틀리(Geoffrey Huntley)가 제안
  - 심슨 가족의 캐릭터 '랄프 위검(Ralph Wiggum)'의 엉뚱하지만 직진하는 성향
  - 아이디어는 간단. 문제가 해결될 때 까지 반복하라

- 랄프 루프 구현을 위한 필수 조건
  - 파일을 통한 작업과 상태 기억
  - 작업마다 새로운 대화(fresh prompt)로 실행
  - [코드->테스트->분석->자가교정] 작업 흐름(workflow), 데이터, 도구를 명시해야 함
  - 명시적이고 정량적인 종료 조건

- 루프 엔지니어링
  - 점점 개발자의 개입이 줄어듬
  - 비용을 고려하지 않는다면 loop 로 못할게 없다는 믿음
  - 더 자율적인 에이전트를 위한 다양한 실험이 이루어짐


## Scene - 스펙 주도 개발, 테스트 주도 개발

- 점점 LLM의 코딩 능력이 향상되고, 운용 노하우도 쌓이고 있다
- 기존 사람 위주의 개발 방법론을 에이전트 위주의 개발 방법론으로 바꿔보자

- 스펙 주도 개발 (Specification-Driven Development, SDD)
  - 점점 강회된 LLM의 코딩 능력에 따라
  - 사람의 역할 변화: 'Coder'에서 'Architect & Spec Writer'로
  -> 에이전트가 명확히 일할 수 있도록 명세(Specification)와 통제 환경(Harness)을 구축하는 개발로 진화

- 테스트 주도 개발 (Test-Driven Development, TDD)
  - 아직 구현하고자 하는 기능의 실제 코드가 없는 상태에서, 그 기능이 동작해야 하는 조건을 담은 테스트 코드를 먼저 작성
  - 테스트 작성 ➔ 코드 작성 ➔ 리팩토링
  - AI 시대에 중요성이 더욱 부각
  - AI의 환각 차단, 자율 루프 검증, 완료 기준(DoD) 확립

- 최신 LLM 들은 어느정도 TDD 에 대한 이해를 하고 있으며, 자체적으로 TDD 개발 방법론을 사용


## Scene - 독립형 에이전트

- 지금까지의 코딩 에이전트는 여전히 "개발자의 작업 공간" 안에 묶인 수동적 상태
  - IDE나 터미널을 열고 세션을 시작해야만 동작
  - 사람이 말을 걸어야만 움직이는 수동적 도구
  - 세션이 끝나면 맥락도 함께 사라짐
  - 에이전트가 내 컴퓨터에 상주하며 알아서 일해줄 수는 없을까?

- 2025년 11월 OpenClaw 의 등장
  - 오스트리아 개발자 피터 슈타인버거(Peter Steinberger)
  - 출발점은 개인적인 필요. 메신저 앱과 개발 도구에서 부를 수 있는 개인 AI 비서
  - Clawdbot → Moltbot → OpenClaw
  - 두 달 남짓 만에 17만 개 이상의 스타를 받으며 역사상 가장 빠르게 성장한 오픈소스 프로젝트 중 하나가 됨



## Scene - 하네스 엔지니어링

- LLM의 코딩 능력이 비약적으로 향상
- 목표를 달성하기 위해 필요한 방법론과 도구가 점점 고도화
- 에이전트가 탈선하거나 맥락을 잃어버리지 않고 목표 지점까지 안전하고 확실하게 다다를 수 있도록 통제망, 평가 지표, 피드백 루프, 실행 환경을 설계에 집중하려는 움직임

- 하네스 엔지니어링
  - 프롬프트 중심에서 표준 명세 문서(Markdown/JSON) 중심으로 전환
    - AGENTS.md, DESIGN.md, .agents folder, rule, memory
  - 자동 피드백 및 백프레셔 (Automated Backpressure):
    - AI가 코드를 고친 후 사람이 직접 확인하지 않아도 되도록, 빌드 도구(npm build), 린터(eslint), 테스트 수트(pytest)를 자동화
  - 자율 무한 루프 제어 (Ralph Loop Harness) 필요성 대두
  - 안전 가드레일 (Safety & Permission Boundary) 필요성 대두

- 하네스 엔지니어링이 확산되면서 점차 에이전트 코딩 방법론이 안정화, 고도화
  - 이 모든 기술들을 집어삼키며 성장하는 LLM

    - 다만 해고의 주원인은 AI가 아니라 경영 및 재무 압박이었고, AI는 신입급 업무를 흡수하는 두 번째 압력으로 작용
  - 스팀: 2026년 6월 14일까지 한 주 동안 출시된 338개 게임 중 120개(약 40%)가 AI 사용을 공개

    - 하지만 AI 공개 게임은 신작의 1/3을 차지하면서도 매출 비중은 10~27%에 불과 → 양은 늘었지만 품질과 수익은 별개
