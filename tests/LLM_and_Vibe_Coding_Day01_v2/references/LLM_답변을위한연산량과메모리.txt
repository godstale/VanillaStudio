# 질문 하나에 상용 LLM이 쓰는 연산과 메모리

**질문:** "'나랏말싸미 듕귁에 달아 문자와로 서로 사맛디 아니할쎄' 이 문장은 어떤 책에 등장하는가?"

---

## 0. 전제

Claude Opus 같은 상용 모델은 구조와 크기가 공개되어 있지 않습니다. 그래서 구조가 공개된 최상위급 모델인 **Llama 3.1 405B**를 기준으로 계산했습니다.

| 항목 | 값 |
|---|---|
| 모델 크기 | 파라미터 **4,050억 개** |
| 구조 | (MHA + FFN) 블록 **126층** · 벡터 폭 16,384 · FFN 폭 53,248 · KV 헤드 8개 |
| 숫자 표현 | BF16 (숫자 하나 = 2바이트) |
| 입력 (prefill) | 질문 약 40토큰 + 대화 형식 토큰 약 10개 = **약 50토큰** |
| 출력 (decoding) | 답변 약 **200토큰** (예: "세종이 쓴 『훈민정음』 언해본 서문에 나오는 문장으로…") |
| GPU | NVIDIA H100 (80GB) **16장** |

토큰 수는 토크나이저마다 다릅니다. 계산량은 토큰 수에 거의 정비례합니다.

---

## 1. 전체 흐름

```
질문(글자) → ① 토큰화 → ② 임베딩 → ③ [MHA + FFN] × 126층 → ④ 다음 단어 예측
                                  └── Prefill: 질문 50토큰을 한꺼번에 처리
                                  └── Decoding: 답변을 한 토큰씩 200번 반복
```

---

## 2. 항목별 비용

### ① 토큰화: 글자를 숫자 조각으로 나누기
- 질문 텍스트는 약 120바이트이고, 약 50개의 토큰 번호가 됩니다.
- 계산 비용은 사실상 0입니다.

### ② 임베딩: 토큰 번호를 의미 벡터로 바꾸기
- 토큰마다 숫자 16,384개짜리 벡터를 표에서 찾아옵니다.
- 이 표의 크기만 **4.2 GB**입니다. 단어장 하나가 영화 몇 편 분량입니다.

### ③-a MHA (Multi-Head Attention): 단어들이 서로를 쳐다보는 단계
- 각 토큰이 Q(내가 찾는 것), K(내가 가진 것), V(내가 전할 내용)를 만들고, 앞 단어들과의 관계를 계산합니다.
- 토큰 1개, 1층 기준 약 **1.1 GFLOP**(11억 번 연산)입니다.
- 이때 만든 **K와 V는 저장해 둡니다.** 이것이 KV cache이고, 답변을 생성할 때 다시 씁니다.

### ③-b FFN (Feed-Forward Network): 각 단어가 지식을 꺼내 오는 단계
- "훈민정음", "세종", "1446년" 같은 지식은 주로 이 거대한 행렬들에 저장되어 있습니다.
- 토큰 1개, 1층 기준 약 **5.2 GFLOP**(52억 번 연산)입니다.
- **전체 연산의 약 82%가 여기서 나옵니다.** 이름은 "Attention is all you need"지만 계산은 대부분 FFN이 합니다.

### ③-c × 126층: 같은 과정을 126번 반복하며 이해를 깊게 하기
- 토큰 1개가 126층을 다 지나면 **약 0.8 TFLOP**(8천억 번 연산)입니다.
- 이 과정에서 모델 가중치 **811 GB** 전체를 한 번씩 읽어야 합니다.

### ④ Prefill: 질문 전체를 한 번에 읽기

| 항목 | 값 | 쉬운 설명 |
|---|---|---|
| 연산량 | **약 40 TFLOP** (40조 번) | 0.8 TFLOP × 50토큰 |
| 읽는 메모리 | **811 GB** | 가중치 전체를 1회 읽음 |
| 남기는 KV cache | **약 25 MB** | 토큰당 504 KB × 50 |
| 걸리는 시간 | 약 15 ms | 계산보다 **메모리를 읽는 시간**이 더 깁니다 |

### ⑤ Decoding: 답을 한 토큰씩 쓰기

| 항목 | 토큰 1개 | 답변 200토큰 전체 |
|---|---|---|
| 연산량 | 약 0.8 TFLOP | **약 160 TFLOP** (160조 번) |
| 읽는 메모리 | 811 GB (매번 전체!) | **약 162 TB** (사용자 1명만 처리할 경우) |
| KV cache 누적 | +504 KB | 최종 약 **126 MB** |
| 시간 | 약 15 ms | 약 3초 |

**핵심:** 단어 하나를 쓸 때마다 811 GB짜리 "뇌" 전체를 처음부터 끝까지 다시 훑습니다. 그래서 decoding은 연산보다 **메모리 속도**가 성능을 좌우합니다. 이 비용을 줄이려고 서비스는 수십~수백 명의 요청을 묶어서(배치) 한 번 읽을 때 함께 처리합니다. 대신 사용자 수만큼 KV cache 메모리가 쌓입니다.

---

## 3. 한눈에 보는 총계

| 구분 | 입력/출력 | 연산량 | 메모리 |
|---|---|---|---|
| 텍스트 | 질문 120 B + 답변 약 0.5 KB | – | – |
| 모델 가중치 | – | – | **811 GB** 상주 (GPU 11장 이상 필요) |
| Prefill | 50토큰 | 40조 번 | 가중치 1회 읽기 + KV 25 MB |
| Decoding | 200토큰 | 160조 번 | 가중치 200회 읽기 + KV 126 MB |
| **합계** | | **약 200조 번** | **가중치 811 GB + KV 126 MB** |

### 쉬운 비유
- 전 인류 80억 명이 1초에 한 번씩 계산해도 **약 7시간**이 걸리는 양입니다.
- 1KB도 안 되는 대화를 위해 811 GB의 가중치를 상주시키고, 처리하는 동안 수백 TB를 읽어 냅니다.
- 원문 120바이트를 기억하는 데 KV cache가 그 **20만 배(25 MB)**나 듭니다.

---

## 4. 실제 서비스는 이보다 더 큽니다

- **시스템 프롬프트:** 상용 서비스는 사용자 질문 앞에 보이지 않는 지시문을 수천 토큰씩 붙이는 경우가 많습니다. 3,000토큰이면 prefill 연산은 **약 60배(2,400조 번)**, KV cache는 **약 1.5 GB**로 늘어납니다.
- **MoE 구조:** 최신 모델은 MoE(전문가 혼합) 구조가 많습니다. 토큰당 연산은 줄지만, 모든 전문가의 가중치를 메모리에 올려 둬야 해서 **메모리 부담은 그대로이거나 더 큽니다.**
- **동시 사용자:** 이 과정을 **수백만 명이 동시에** 실행합니다.
