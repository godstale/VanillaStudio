# 사용자 체크리스트 — 사람이 직접 만들거나 결정해야 할 것

> 에이전트가 대신할 수 없거나, 대신하면 제품 의도가 흐려지는 항목들입니다.
> 새 프로젝트를 시작할 때 이 목록을 복사해 체크하세요.

## P0 준비

- [ ] 스타터 템플릿 선택(기술 스택 고정 여부 판단)
- [ ] 사용할 코딩 에이전트와 구독 계정 준비
- [ ] 공통 스킬 선택(예: wiki, grill-me, 코드 스타일)
- [ ] 저장소 위치·원격 저장소 여부 결정

## P1 요구사항

- [ ] **요구사항 문서 직접 작성**: 한 줄 정의, 왜 만드는가, 사용자 흐름, 최종 결과물, 확장 계획
- [ ] 참고 서비스·레퍼런스 목록
- [ ] 절대 하지 않을 것(Non-goals) 명시 — 예: Vanilla Studio의 "생성형 AI 배제"

## P2 상세 기획

- [ ] 인터뷰 질문에 대한 결정(연동 방식, MVP 범위, 대상 OS, 정책 등)
- [ ] 에이전트가 제안한 `Proposed` 결정 검토 → Accepted/거절
- [ ] 기획서 승인
- [ ] 라이선스 리스크에 대한 판단(필요 시 법률 검토)

## P3 구현 계획

- [ ] 마일스톤 우선순위와 일정 감각
- [ ] PoC 실패 시 대안 선택
- [ ] 품질 기준이 될 **골든 샘플 시나리오** 작성(예: 샘플 브리프 5종)

## P4 구현

- [ ] 마일스톤 데모 확인 및 방향 피드백
- [ ] 브랜딩 자산(앱 이름, 로고, 아이콘, 색) — `BRANDING.md` 절차
- [ ] UI 문구 톤(ko/en)

## P5 검증

- [ ] 실제 사용해 보기, 버그·불편 보고
- [ ] 릴리스 가능 판단

## P6 릴리스

- [ ] 버전 번호, 릴리스 노트 검토
- [ ] 코드 서명 인증서, 배포 채널(GitHub Releases 등)
- [ ] **push·배포 실행 승인**

## P7 회고

- [ ] 단계별 회고에 사람 관점의 교훈 추가
- [ ] 강의에서 보여줄 장면·자료 선정
