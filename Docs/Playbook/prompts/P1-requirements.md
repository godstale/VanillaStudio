# P1 요구사항 — 프롬프트

## 1. 실제 사용 원문 (Vanilla Studio)

요구사항 문서는 **사용자가 직접 작성**했다(`Docs/Vanilla-Studio-Requirements.txt`). 에이전트 프롬프트는 사용하지 않았다.
문서 구성: ① 앱 정의와 철학(왜 "바닐라"인가) ② 동작 구조 7단계 ③ 최종 결과물 ④ 디자인 템플릿 ⑤ 플레이그라운드.

**관찰**: 철학(최소 제약·생성형 AI 배제)과 사용자 흐름(7단계)이 명확해 P2 기획이 빠르게 진행되었다.
반면 "수동 조절", "패키지 형태" 같은 표현은 구현 수준이 모호해 P2 인터뷰에서 구체화가 필요했다.

## 2. 일반화 템플릿 — 요구사항 검토 요청 (사용자가 초안을 쓴 뒤)

```text
{{REQUIREMENTS_PATH}}에 요구사항 초안을 작성했다. 아직 기획 단계로 넘어가지 말고 다음만 해라.
1. 빠진 항목(대상 사용자, 핵심 흐름, 결과물, 범위 밖, 확장 계획)을 지적하라.
2. 구현 수준이 모호한 표현을 인용하고, 각각 어떤 질문으로 구체화할지 제안하라.
3. 문서를 직접 수정하지 말고 질문 목록으로만 답하라.
```
