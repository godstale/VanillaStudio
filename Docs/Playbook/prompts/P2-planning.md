# P2 상세 기획 — 프롬프트

## 1. 실제 사용 원문 (Vanilla Studio, 2026-09-28)

### 1.1 킥오프 프롬프트 (사용자 → 에이전트)

```text
현재 프로젝트를 바닐라(Vanilla) 스튜디오 앱으로 만들려고 한다.
바닐라 스튜디오는 tauri 기반의 앱으로 파워포인트 또는 웹 사이트, 동영상, 애니메이션 등을 심미적으로 띄어난 형태로 디자인하기 위한 도구이다.
프로젝트 구현을 위한 앱 소개와 요구사항들을 @Docs\Vanilla-Studio-Requirements.txt 문서에 기록해 두었다.
이 문서를 바탕으로 앱 기획을 시작하자.

앱 구현을 위해 아래 순서로 작업할 예정이다.
Requirements 작성 -> 상세 기획서 작성 -> 구현 계획서(+TODO) 작성 -> 구현 -> 검증/테스트/수정 루프

Requirements 문서는 작성되었고 상세 기획서를 작성할 차례이다.
- 기획서 작성을 위해 앱의 전반적인 요구사항들을 면밀히 검토하고 실제 구현이 어려운 부분들을 확인하자.
- 실제 구현이 가능한 형태로 기획을 하고 구현에 필요한 기술 스택 등을 정의하자.
- 필요하다면 외부 자료를 리서치해서 자료를 보강하자.
- 기획 과정에서 필요하다면 적극 인터뷰를 진행해서 내용을 명확히 하자.
- 기획된 결과는 기획 문서로 저장되어야 한다.
- 기획이 완료되면 앱 프로젝트를 시작하기 위한 지침 파일(AGENTS.md)을 작성하고 기타 기본 파일들이 있는지 점검하자.
- 진행 내용을 wiki 를 이용해서 상세히 기록하자. 기획 뿐 아니라 설계, 구현 단계에서도 wiki 가 항상 지식베이스로 작동하도록 내용을 구조적으로 분류해서 기록해두자. 이 내용은 지침 파일에도 저장해서 항상 지켜져야 한다.
- requirement 단계부터 구현 완료 및 배포까지의 전 과정을 단계별로 구분하고 각 단계에서 해야할 일, 산출물 들이 무엇인지 기록하자. 이 내용은 추후 바이브 코딩 강의에도 사용될 예정이므로 미리 이런 요구사항에 맞춰 자료를 수집하고 저장해두어야 한다. 이것도 지침 파일에 기록해서 항상 지켜지도록 하자.
```

사용자가 자유 응답으로 방향을 바꾸는 경우(동영상 범위, 강의 자료 목적)가 가장 중요한 정보이므로 반드시 문서에 원문 반영.

## 2. 일반화 템플릿

```text
{{APP_NAME}}의 요구사항 문서({{REQUIREMENTS_PATH}})를 바탕으로 상세 기획을 진행하자.
작업 순서: Requirements → 상세 기획서 → 구현 계획서(+TODO) → 구현 → 검증/테스트/수정 루프 → 배포.
지금은 상세 기획 단계다.

1. 요구사항을 항목별로 검토하고, 구현이 어려운 부분과 그 이유(기술·라이선스·성능·보안)를 표로 정리하라.
2. 외부 리서치로 대체 기술·성숙도·라이선스를 확인하고 출처를 남겨라.
3. 결정이 필요한 부분은 인터뷰로 물어라. 각 질문에 선택지·권장안·트레이드오프를 붙이고 한 번에 4개 이하로.
4. 산출물:
   - Docs/Planning/Product-Spec.md (제품 정의, 사용자 여정, 화면/IA, 기능 명세(M/S/L), 데이터 계약, 비기능, 로드맵)
   - Docs/Planning/Technical-Design.md (구성도, 스택, 핵심 모듈 설계, 데이터 저장, 보안, 테스트 전략, ⚠️ 가정 표시)
   - Docs/Planning/Feasibility-Risks.md (요구사항별 가능성, 난점·대응, 라이선스, PoC 계획, 출처)
   - Docs/Planning/Decisions.md (결정 기록 D-NNN)
5. AGENTS.md(프로젝트 지침)를 갱신하고 기본 파일(CLAUDE.md, README, .gitattributes 등)을 점검하라.
6. 진행 내용을 wiki/에 구조적으로 기록하고, 단계별 플레이북(Docs/Playbook)을 갱신하라.
```
