# P4 구현 — 프롬프트

> 상태: 템플릿 초안. 마일스톤 수행 시 실제 사용 원문을 §1에 추가한다.

## 1. 실제 사용 원문

### 1.1 병렬 세션 준비 (2026-09-29, P4 착수 전)

```text
다른 에이전트를 이용해서 새로운 세션에서 구현 작업을 병렬로 실행할 것이다. 편의를 위해 다음 실행할 작업 진입점을 표시해두고, 어떤 파일들을 참고해서 작업을 배치하고 실행해야 할지 적어두자.
```

- 에이전트는 TODO 의존성으로 웨이브·레인을 나눴다. 구성은 웨이브 0 단독 → 웨이브 1 레인 4개 → 웨이브 2 레인 2개다.
- 레인마다 소유 경로를 정하고, 공유 파일(i18n·lib.rs·의존성·마이그레이션·TODO·wiki)의 편집 규칙을 정했다.
- 세션 시작 프롬프트와 완료 보고 형식을 `Docs/Planning/Parallel-Execution.md`에 두었다.
- 교훈: 루트 설정(워크스페이스·lint·test)을 바꾸는 항목은 병렬 전에 단독으로 끝낸다. DB 마이그레이션 번호처럼 순서가 있는 자원은 한 레인에만 준다.

### 1.2 v2 구현 V1~V7 (2026-10-05~06, 사용 한도로 중단 후 재개)

처음 요청은 "v2 구현 계획(V1~V7)을 TODO 순서대로 구현하라"였고, V1~V4 일부(T4.1~T4.7)까지 진행한 뒤 사용 한도로 멈췄다. 에이전트의 마지막 보고(완료·남은 것·알려진 빈틈·검증 상태)를 그대로 붙여 이어가게 했다.

```text
아래 메시지와 같이 사용한도로 작업이 멈추었다. 중단된 작업을 다시 시작해줘. 남은 구현 작업을 완료해줘.

사용 한도에 도달해 여기서 멈춥니다. V1~V3과 V4의 T4.1~T4.7까지 끝났고, V4의 T4.8~T4.12와 V5~V7은 남았습니다.
(검증 상태·브랜치/푸시 상태·완료 목록·남은 것·알려진 빈틈을 이어서 붙인다)
```

- 이어받는 에이전트는 `TODO.md` 진입점과 `git log`로 상태를 다시 확인하고, 항목 단위로 테스트 → 커밋 → TODO 체크 → 마일스톤 로그를 이어갔다.
- 효과적이었던 점: ① 중단 보고에 **"검증하지 않은 것"**(GUI·실제 에이전트·전체 cargo test)이 명시되어 있어 재개 후 제일 먼저 다시 돌릴 것이 분명했다. ② push가 한 번도 없었다는 사실이 적혀 있어 병합·브랜치 상태를 헷갈리지 않았다.
- 교훈: **한도로 멈출 가능성이 있는 긴 작업은 항목마다 커밋하고 TODO를 체크**해 두면 재개 비용이 거의 없다. 마지막 보고 형식(완료·남은 것·알려진 빈틈·검증 상태)을 고정해 두면 다음 세션이 그대로 이어받는다.

(이후 마일스톤별로 기록)

## 2. 일반화 템플릿

### 2.1 마일스톤 시작

```text
Docs/Planning/TODO.md의 마일스톤 {{MILESTONE}}을 시작하라.
- AGENTS.md의 git 규칙대로 main에서 {{BRANCH}} 브랜치를 만든다.
- wiki/index.md에서 관련 지식(결정·PoC·개념)을 먼저 조회하라.
- TODO 순서대로 진행하고, 항목마다 테스트 → 커밋(Conventional Commits) → TODO 체크.
- 설계와 다르게 구현해야 하면 멈추고 이유와 대안을 보고하라.
```

### 2.0 중단된 작업 재개 (사용 한도·세션 종료 후)

```text
{{중단 사유}}로 작업이 멈추었다. 중단된 작업을 다시 시작해줘. {{남은 범위}}를 완료해줘.

{{이전 세션의 마지막 보고 전문: 완료 목록, 남은 것, 알려진 빈틈, 검증 상태(통과·미실행), 브랜치·push 상태}}
```

재개 첫 단계: `git status -sb`·`git log --oneline -5`·`TODO.md` 진입점으로 실제 상태를 확인하고, **보고에 "미실행"으로 적힌 검증부터 다시 돌린다**.

### 2.2 마일스톤 마무리

```text
마일스톤 {{MILESTONE}}을 마무리하라.
1. pnpm lint / typecheck / test 결과를 보고하라.
2. 변경된 구조를 Docs/(Project-Structure, Technical-Design)에 반영하라.
3. wiki/sources/milestone-{{MILESTONE}}.md에 한 일·결정·문제·해결·교훈을 기록하고 index/log를 갱신하라.
4. 이번 마일스톤에서 효과적이었던 프롬프트를 Docs/Playbook/prompts/P4-build.md §1에 추가하라.
5. push는 하지 말고 승인을 요청하라.
```

### 2.3 병렬 세션 배치 (여러 에이전트)

```text
Docs/Planning/TODO.md의 {{MILESTONE}} 항목을 여러 세션에서 병렬로 실행할 수 있게 배치하라.
1. 선행 관계로 웨이브를 나눈다. 루트 설정·공용 스키마를 바꾸는 항목은 웨이브 0(단독)에 둔다.
2. 웨이브마다 레인을 정하고, 레인별 소유 경로(디렉터리)를 겹치지 않게 지정한다.
3. 공유 파일(i18n 사전, 명령 등록부, 의존성 목록, 마이그레이션 번호, TODO, wiki)의 편집 규칙을 정한다.
4. 통합 브랜치 + 레인별 워크트리 명령, 병합 순서, 조정 세션의 역할을 적는다.
5. 레인별 세션 시작 프롬프트(읽을 파일, 담당 항목, 소유 경로, 참고 PoC)와 완료 보고 형식을 만든다.
6. TODO 맨 위에 "▶ 진입점"을 표시하고, 항목마다 [레인 · 웨이브] 태그를 붙인다.
```

### 2.4 레인 세션 시작

```text
{{APP_NAME}} 구현, 레인 {{LANE}}을 수행하라.
- 워크트리 {{WORKTREE}}, 브랜치 {{BRANCH}}. 이 워크트리 밖은 수정하지 않는다.
- AGENTS.md와 {{PARALLEL_GUIDE}}(공통 참고 파일, 공유 파일 규칙, 운영 규칙)를 먼저 읽는다.
- 담당 항목 {{TODO_IDS}}, 소유 경로 {{OWNED_PATHS}}. 소유 경로 밖 변경이 필요하면 멈추고 보고한다.
- 항목마다 검증 → 커밋(항목 ID 포함) → TODO 체크. push·병합 금지. 끝나면 완료 보고 형식으로 보고한다.
```
