# 파이프라인 (Pipeline) — Brief → Export

Vanilla Studio의 제작 흐름은 6단계입니다. 왼쪽 **파이프라인** 패널에 현재 단계와 완료 상태(진행 중·승인됨·완료·잠김)가 표시됩니다.
이후 단계의 승인·완료를 초기화하는 **다시 열기** 동작이 있습니다(확인 필요: 초기화 범위).

## 1. 단계 1 — 브리프 (사용자 작성)

**브리프** 탭에서 무엇을 만들지 적습니다.

- 구조화 폼: 목적(필수)·대상·핵심 메시지·톤앤매너·브랜드 색·폰트·필수 포함 요소·금지 사항·참고 자료 + 자유 서술
- 브랜드 색은 `#RRGGBB` 형식만 쓸 수 있습니다
- 자료(이미지·로고·텍스트·PDF·CSV 등)는 **자료 추가**로 `brief/materials/`에 복사하고, 라이선스·출처를 함께 적습니다
- **저장** 후 **브리프 완료**를 누르면 다음 단계로 넘어갈 준비가 됩니다
- 산출물: `brief/brief.md`, `brief/materials/*`, `vanilla.json`, `DESIGN.md`(초기본)

## 2. 단계 2 — 기획서 Plan (에이전트 작성·사용자 승인)

1. **기획서 생성 요청**을 누릅니다. 먼저 **에이전트 세션을 시작**해야 합니다(세션 없이 요청하면 안내가 표시됩니다).
2. 에이전트가 세 파일을 작성합니다.
   - `DESIGN.md` — 디자인 시스템(색·타이포 토큰 + 사용 원칙). 초기본을 브리프·무드에 맞게 다듬습니다
   - `plan/plan.md` — 사람용 기획서(콘셉트·무드·Scene별 설명·스토리보드 서술)
   - `plan/plan.json` — 기계용 구조(Scene·Asset·애니메이션 타임라인·구현 방법·조절 가능 파라미터)
3. 앱이 `plan.json`을 스키마로, `DESIGN.md`를 형식 검사(구조·토큰 참조·필수 색 역할·대비)로 검증합니다.
   실패하면 오류 목록을 에이전트에게 **최대 2회까지 자동 재요청**하고, 그래도 안 되면 사용자에게 표시됩니다.
4. **기획서 뷰어**에서 스토리보드 카드·타임라인 막대·Asset 목록·파라미터 표·디자인 요약·`plan.md` 미리보기를 확인합니다.
   이 단계에서 팔레트를 바꿔 보며 무드를 정할 수 있습니다(에이전트 재호출 없음).
5. 코멘트를 달아 **수정 요청**을 하거나 **승인**합니다. 승인 시 체크포인트 커밋이 생기고 구현 프롬프트 단계가 열립니다.

## 3. 단계 3 — 구현 프롬프트 Prompts (에이전트 작성·사용자 승인)

- 승인된 기획서를 바탕으로 에이전트가 `prompts/00-master.md`(전체 순서·원칙),
  `prompts/assets/<id>.md`·`prompts/animations/<id>.md`·`prompts/scenes/<scene-id>.md`(개별 계획서),
  `prompts/tasks.json`(태스크 목록·의존성)을 작성합니다.
- **프롬프트 편집기**(트리 + 코드 편집기)에서 직접 수정할 수 있습니다. 저장하지 않은 변경은 표시됩니다.
- **태스크 그래프**에서 의존성 순서와 상태(대기·진행·완료·실패)를 봅니다. 의존성에 순환이 있으면 경고가 표시됩니다.
- **승인**하면 체크포인트 커밋이 생기고 구현 단계가 열립니다.

## 4. 단계 4 — 구현 Build (에이전트 실행)

- **빌드 시작**을 누르면 `tasks.json`의 위상 정렬 순서대로 태스크를 하나씩 에이전트에게 보냅니다(태스크 = 에이전트 요청 1회).
- 실행 모드: **자동(순차 전체)** / **한 단계씩(태스크마다 확인)**. 일시정지·재시도가 가능합니다.
- 각 태스크 완료 후 앱이 ① 런타임 계약 검사(`check_scene`, 하드코딩 색상 경고 포함) ② 스냅샷 생성
  ③ 체크포인트 커밋을 수행하고 다음 태스크로 넘어갑니다(확인 필요: 자동 수행 범위).
- **에이전트 패널**(우측 도크)에서 진행 로그(메시지·도구 호출·파일 diff)를 보고 **중단**할 수 있습니다.
- 셸 실행·네트워크 같은 권한 요청은 **매번 확인 다이얼로그**가 뜹니다. "이번만 허용 / 거부" 중 고릅니다.
  프로젝트 폴더 밖 파일 접근은 거부됩니다.
- 태스크 실행 상태는 프로젝트 DB(`.vanilla/app.db`의 `task_runs`)에 저장됩니다. 파일(`tasks.json`)은 선언, DB는 상태입니다.

## 5. 단계 5 — 검수 Review (사용자 확인·조절)

**검수** 탭이 핵심 화면입니다. 왼쪽 Scene 목록 · 가운데 미리보기(iframe) + 타임라인 · 오른쪽 파라미터/디자인 패널 ·
아래 수정 요청栏으로 구성됩니다.

- **미리보기**: 프로젝트의 프리뷰 서버(Vite)를 iframe으로 표시합니다. 규격 비율 유지, 확대/맞춤,
  배경(체커·캔버스·밝게·어둡게), 웹 기기 폭(데스크톱·태블릿·모바일) 전환이 있습니다.
  서버 시작 실패·의존성 미설치·미신뢰 폴더에서는 각각 안내와 재시도 버튼이 표시됩니다.
- **타임라인 스크러버**(시간 기반 유형): 재생/정지·한 프레임 이동·이전/다음 Scene·구간 반복·Scene 경계 표시.
  `web`·`interactive`(자유 모드)는 재생/정지·새로고침만 제공합니다.
  키보드: `Space` 재생/정지, `←`/`→` 프레임 이동.
- **파라미터 패널**: `plan.json`에서 선언되고 코드에 등록된 파라미터를 폼으로 조절합니다.
  변경은 즉시 미리보기에 반영되고, **저장** 시 `params/<scene>.values.json`에 기록 + 체크포인트가 생깁니다.
- **디자인 패널**(파라미터 옆 탭): 현재 팔레트 스와치, 라이브러리에서 교체(선택 즉시 미리보기 반영, 파일 변경 없음),
  **적용** 시 `DESIGN.md`의 `colors` 토큰만 교체 + 체크포인트. 대비 기준 미달 쌍은 경고가 표시됩니다(적용은 됨).
- **수정 요청**: 대상 Scene + 시각(초, 비워 두면 전체) + 코멘트 + 스크린샷 첨부 여부 →
  ① `reviews/R-NNN.md` 생성 ② 대상 구현 계획서에 Revision 섹션 추가 ③ 에이전트에 반영 요청 ④ 완료 시 이전/이후 비교.
  활성 에이전트 세션이 없으면 전송이 아니라 대기 상태로 남습니다.
- **전/후 비교**: 두 체크포인트의 스크린샷을 나란히 봅니다. 스크린샷이 없는 시점은 비교할 수 없습니다.

## 6. 단계 6 — 내보내기 Export (앱이 백그라운드 실행)

- **내보내기** 탭에서 유형별 옵션을 정하고 작업을 대기열에 추가합니다. 진행률·로그·취소가 작업마다 표시됩니다.
- 결과는 `exports/<시각>-<형식>/` 폴더에 저장됩니다. 완료 후 **플레이그라운드에 추가**할 수 있습니다.
- 형식별 옵션과 제약은 `04-export-limits.md`를 참고하세요.

## 7. 체크포인트

- Plan 승인·Prompts 승인·태스크 완료·파라미터 저장·팔레트 적용 같은 지점에서 체크포인트가 생깁니다.
- Git이 있는 프로젝트는 자동 커밋, 없으면 폴더 스냅샷 방식으로 기록됩니다(확인 필요).
- 체크포인트 목록에서 히스토리를 보고 비교·되돌리기를 할 수 있습니다(확인 필요: 되돌리기 UI 위치).
