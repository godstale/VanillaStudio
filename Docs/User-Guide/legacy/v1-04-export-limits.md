# Export 형식별 제약 (Export Limits)

내보내기 탭에서 유형별 옵션을 정하고 작업을 대기열에 추가하면 앱이 백그라운드에서 실행합니다.
진행률·로그·취소가 작업마다 표시되고, 결과는 `exports/<시각>-<형식>/`에 저장됩니다.
완료된 작업은 **플레이그라운드에 추가**해 보관·재생할 수 있습니다.

공통 전제: 캡처 기반 형식(image·slides·video)은 **렌더 브라우저**(Chrome Headless Shell)와
프로젝트 의존성 설치가 필요합니다. 준비 신호(`__vanillaReady`)를 기다렸다가 캡처하므로,
준비 신호를 보내지 않는 Scene은 타임아웃으로 실패합니다.

## 1. 웹 / 인터랙티브 — 정적 사이트 zip (+ 임베드 패키지)

- `vite build`(live 빌드) 결과를 zip으로 묶습니다. 풀어서 정적 서버로 열면 동작합니다.
- 임베드 패키지(ES 모듈 + Web Component `<vanilla-scene>` + React 래퍼)는 별도 산출물입니다(확인 필요: 다이얼로그 노출 여부).
- `web`·`interactive` 유형의 애니메이션은 자유 모드(실시간 코드)라 캡처 기반 export와 달리 시간 결정성이 보장되지 않습니다.

## 2. 이미지 — PNG / JPG / WebP, 배율, 변형 일괄

- 파일 형식(PNG·JPG·WebP)과 배율(@1x/@2x 등), 크기를 고릅니다.
- 파일명은 기본 `<이름>@<배율>x.<확장자>` 형식입니다.
- 여러 규격 변형을 한 작업으로 일괄 출력할 수 있습니다(확인 필요: 변형 선택 UI).
- 고해상도(예: 3840×2160)는 배율을 올려 반복 캡처하며, 같은 입력에서는 같은 결과가 나옵니다.

## 3. 슬라이드 — PPTX(이미지) · PDF

- 각 슬라이드를 이미지로 캡처해 PPTX·PDF로 묶습니다.
- 장수·페이지 크기는 내보내기 옵션(슬라이드 수·크기)에서 정합니다.
- 슬라이드 내 빌드 애니메이션(단계별 등장 효과)은 이미지/PDF에 담기지 않습니다.
  애니메이션이 필요하면 HTML 덱(확인 필요: 제공 여부)을 쓰세요.

## 4. 슬라이드 — 편집 가능 PPTX (Beta)

- 이미지 PPTX와 함께 **편집 가능 PPTX(Beta)** 를 추가로 만들 수 있습니다.
- 방식: 슬라이드 DOM을 `dom-to-pptx` 브라우저 번들로 변환해 텍스트 편집이 가능한 도형으로 만듭니다.
- 알려진 제약:
  - 대상 PC에 설치된 폰트로 표시됩니다. 사용된 웹 폰트 파일과 설치 안내(`FONTS-README.md`)가 결과물에 함께 들어갑니다(최대 24개).
  - 그라디언트·그림자 등 효과는 근사치로 변환됩니다.
  - WebGL 캔버스가 있으면 `preserveDrawingBuffer` 옵션이 켜진 Scene만 변환되며, 나머지는 비어 보일 수 있습니다.
  - 한 줄 텍스트 상자는 줄바꿈 방지 후처리(`wrap="none"`)가 적용됩니다. 그래도 겹침이 보이면 원본 Scene의 배치를 확인하세요.
- **Beta**이므로 PowerPoint에서의 육안 확인을 권장합니다.

## 5. 영상 — MP4(H.264) · WebM + 포스터 PNG

- render 빌드 → HyperFrames render → MP4/WebM 인코딩 + 포스터 스틸 순서로 실행됩니다.
- 옵션: 크기(프리셋 FHD·HD·정사각·세로·4K 또는 직접 입력), FPS, 길이(초), 컨테이너(MP4/WebM).
- 전제 조건:
  - **FFmpeg(libx264 포함)** — Doctor에서 앱 내 내려받기 가능(`02-doctor.md` §2).
  - `video` 유형 Scene은 **시간 함수 계약**을 지켜야 합니다(같은 시각 `t` → 같은 화면).
    `Date.now()`·누적형 애니메이션·시드 없는 난수는 결정성을 깨고, 두 번 렌더 결과가 달라질 수 있습니다.
  - 렌더 워커 수는 메모리 기준(약 4GiB당 1개, CPU 수 상한)으로 자동 결정됩니다.
- 투명 배경 export는 제공하지 않습니다(로드맵 대상).
- 긴 영상·4K 렌더는 시간과 메모리를 많이 씁니다. 작업 중 취소할 수 있습니다.

## 6. 실패 시 확인 순서

1. 설정 → 환경 점검에서 관련 항목(FFmpeg·렌더 브라우저·Node·pnpm)이 정상인지 확인
2. 작업 로그에서 실패 단계 확인(빌드 실패 vs 캡처 타임아웃 vs 인코딩 실패)
3. 캡처 타임아웃이면 미리보기에서 해당 Scene이 정상 표시되는지 확인(준비 신호·콘솔 오류)
4. 빌드 실패면 프로젝트 의존성이 설치되어 있는지 확인
