# 시작하기 (Getting Started)

Vanilla Studio에 오신 것을 환영합니다. 코딩 에이전트가 브라우저 기술(HTML/CSS/JS·React·three.js)로
웹 페이지·슬라이드·이미지·영상을 만들고, 사용자는 기획·검수·미세조정에 집중하는 데스크탑 앱입니다.

> 이 문서는 앱 저장소의 `Docs/User-Guide/`에 있으며, 앱 안 **설정 → 앱 → 사용자 문서**에서도 링크를 볼 수 있습니다.

## 1. 준비물

| 항목 | 요구 | 비고 |
| --- | --- | --- |
| OS | Windows 10/11 64비트 | macOS/Linux는 공식 지원이 아닙니다(확인 필요) |
| Node.js | 22 이상 | Doctor가 버전을 검사합니다 |
| pnpm | Node corepack으로 활성화 | `corepack enable pnpm` |
| Git | 체크포인트(자동 커밋)에 사용 | 없으면 폴더 스냅샷 방식으로 기록됩니다 |
| 코딩 에이전트 CLI | 최소 1개 (Claude Code·Codex·OpenCode·Hermes·AGY) | 설정 → 환경 점검에서 상태 확인 |
| FFmpeg | 영상 내보내기(video)에만 필요 | 앱 안에서 내려받기 가능(§3) |
| 렌더 브라우저 | 이미지·슬라이드·영상 캡처에 사용 | Chrome Headless Shell |

설치 상태가 의심스러우면 **설정 → 환경 점검(Doctor)** 을 먼저 여세요. 자세한 내용은 `02-doctor.md`를 참고하세요.

## 2. 첫 프로젝트 만들기

1. 앱을 실행하면 시작 화면이 나옵니다. **새 프로젝트**를 고릅니다.
2. 마법사에서 다음을 선택합니다.
   - **결과물 유형**: 웹 페이지·인터랙티브·슬라이드·이미지·영상
   - **규격**: 해상도·FPS·길이·슬라이드 수·이미지 변형 등 (유형에 따라 다름)
   - **템플릿**: 없음 또는 갤러리의 내장 템플릿
   - **팔레트**: 기본 또는 라이브러리에서 선택
   - **기본 에이전트**: 이 프로젝트에 주로 쓸 에이전트
   - **저장 위치**: 프로젝트를 만들 상위 폴더
3. **만들기**를 누르면 프로젝트 폴더가 생성되고 탭이 열립니다.
   이때 `pnpm install` 실행에 대한 동의를 1회 묻습니다(고정 명령만 실행, `package.json`이 바뀌면 다시 묻습니다).
4. 처음 여는 폴더는 **신뢰 확인**이 뜹니다. 출처를 아는 자신의 폴더만 신뢰하세요.
   신뢰하기 전에는 에이전트 세션 시작과 미리보기 서버 시작이 비활성화됩니다.

## 3. 제작 흐름 한눈에 보기

왼쪽 **파이프라인** 패널에 6단계가 표시됩니다. 잠긴 단계는 이전 단계의 승인이 필요합니다.

```
[1 브리프] → [2 기획서] → [3 구현 프롬프트] → [4 구현] → [5 검수] ⇄ (수정 요청) → [6 내보내기]
 사용자 작성   에이전트 작성·사용자 승인   에이전트 작성·사용자 승인   에이전트 실행   사용자 확인·조절   앱이 백그라운드 실행
```

1. **브리프** 탭에서 목적·대상·핵심 메시지를 적고 **브리프 완료**를 누릅니다.
   참고 자료(이미지·로고·PDF 등)는 `brief/materials/`에 넣고 라이선스·출처를 함께 적습니다.
2. **기획서** 탭에서 **기획서 생성 요청**을 누릅니다. 에이전트 세션이 먼저 시작되어 있어야 합니다.
   앱이 `plan/plan.json`을 스키마로 검증하고, 실패하면 최대 2회까지 자동으로 다시 요청합니다.
   내용을 확인하고 **승인**하면 체크포인트(자동 커밋)가 생기고 다음 단계가 열립니다.
3. **구현 프롬프트** 탭에서 프롬프트 트리를 확인·편집하고 **승인**합니다.
4. **구현** 단계는 태스크를 순서대로 에이전트에게 보냅니다. **자동(순차 전체)** 또는 **한 단계씩** 모드를 고를 수 있습니다.
   진행 로그·파일 diff는 에이전트 패널(우측 도크)에서 보고, 셸 실행 같은 권한 요청에는 매번 답해야 합니다.
5. **검수** 탭에서 미리보기를 보며 파라미터를 조절하고, 필요하면 수정 요청을 보냅니다.
6. **내보내기** 탭에서 유형별 옵션을 정하고 작업을 시작합니다. 끝나면 **플레이그라운드에 추가**할 수 있습니다.

자세한 단계별 설명은 `03-pipeline.md`, 형식별 제약은 `04-export-limits.md`를 참고하세요.

## 4. 알아두면 좋은 것

- **모든 것은 파일입니다.** 프로젝트 내용(brief·plan·prompts·src·params·reviews)은 폴더 안 파일이 진실 공급원이고,
  DB(`.vanilla/`)에는 UI 상태·실행 상태만 둡니다. 파일은 직접 열어 봐도 됩니다.
- **사용자 조절값은 보호됩니다.** `params/*.values.json`과 승인 이후의 `DESIGN.md` 토큰 값은
  사용자가 명시적으로 바꾸지 않는 한 앱·에이전트가 덮어쓰지 않습니다.
- **색은 토큰으로만 씁니다.** 코드에 색을 직접 적지 않고 `DESIGN.md`의 토큰(`--color-*`, `useDesign()`)을 참조합니다.
  팔레트를 바꾸면 에이전트를 부르지 않고도 결과물의 느낌이 바뀝니다.
- **생성형 이미지·영상 AI는 쓰지 않습니다.** 결과물은 코드(절차적 생성)와 사용자 자료, 오픈 라이선스 리소스로 만듭니다.
  외부 리소스를 쓰면 `assets/CREDITS.md`에 출처를 기록해야 합니다(확인 필요: 자동 기록 여부).
- 키보드: 미리보기에서 `Space` 재생/정지, `←`/`→` 프레임 이동(영상·시간 기반 Scene).

## 5. 문제가 생기면

| 증상 | 해법 |
| --- | --- |
| 에이전트 세션이 시작되지 않음 | 폴더 신뢰 여부 확인 → 설정 → 환경 점검에서 해당 CLI 상태 확인 |
| 미리보기가 연결되지 않음 | 프로젝트 의존성 설치 여부 확인(설치 안내 다이얼로그) → 미리보기 서버 재시작 |
| 영상 내보내기 실패 | FFmpeg(libx264 포함) 설치 여부 확인 → `02-doctor.md` 참고 |
| 기획서 검증 반복 실패 | 오류 목록을 확인하고 브리프를 더 구체적으로 적은 뒤 다시 요청 (2회 초과 시 사용자에게 표시됨) |
