# Doctor — 환경 점검 (Environment Check)

**설정 → 환경 점검**에서 Vanilla Studio가 사용하는 외부 도구의 설치 상태를 확인합니다.
시작 화면에도 요약 배지가 표시됩니다.

## 1. 점검 항목

각 항목은 **정상 / 없음 / 업데이트 필요 / 지원 안 됨 / 로그인 필요 / 참고** 중 하나로 표시되며,
버전·경로가 함께 나옵니다. 문제가 있으면 항목마다 해결 방법이 표시되고, 명령은 복사 버튼으로 복사할 수 있습니다.

| 항목 | 구분 | 설명 |
| --- | --- | --- |
| Node.js | 필수 | 22 이상 필요. 낮으면 LTS로 올리라는 안내가 나옵니다 |
| pnpm | 필수 | Node corepack으로 켭니다(`corepack enable pnpm`) |
| Git | 권장 | 워크스페이스 폴더를 버전 관리할 때 사용합니다. 앱 동작에는 필수가 아닙니다 |
| Claude Code | 조건부 필수 | 코딩 에이전트 최소 1개 필요. 없으면 "사용 가능한 에이전트가 없음" 요약이 표시됩니다 |
| Claude Code 로그인 | 참고 | 로그인 상태를 확인하지 못하면 별도 안내가 표시됩니다 |
| Codex | 선택 | 설치 안내 참고 |
| OpenCode | 선택 | 설치 안내 참고 |
| Hermes | 선택 | 설치 안내 참고 |
| AGY | 선택 | 앱이 터미널에서 실행합니다 |
| FFmpeg | 영상 레퍼런스의 키프레임 추출 시 필요 | 앱이 관리하는 최신 빌드가 PATH의 오래된 빌드보다 우선합니다. 아래 §2 참고 |
| 렌더 브라우저 (Chrome Headless Shell) | v2.0에서는 쓰지 않음 | 이미지·영상 내보내기(후속 기능)용 항목입니다 |
| WebView2 런타임 | 필수(Windows) | 설치 후 앱 재시작 |
| winget | 설치 도우미 | 없으면 각 안내 페이지에서 직접 설치해야 합니다 |

> 에이전트는 공식 지원(Claude Code·Codex)과 실험적(OpenCode·Hermes·AGY) 등급으로 구분됩니다.
> 등급별 동작 차이는 설정의 에이전트 목록에서 흡수되며, 신 실행·검토 흐름은 에이전트 종류와 무관합니다.

## 2. FFmpeg 내려받기 (앱 내 설치)

영상 레퍼런스에서 키프레임과 메타데이터를 뽑으려면 FFmpeg(`ffmpeg`·`ffprobe`)가 필요합니다. 오래된 빌드는 옵션을 지원하지 않아 실패할 수 있으니 앱이 내려받는 최신 빌드를 권장합니다.
Doctor의 FFmpeg 항목에서 **FFmpeg 내려받기**를 누르면 동의 다이얼로그가 뜹니다.

- **출처**: GitHub BtbN/FFmpeg-Builds 최신 릴리스
- **설치 위치**: 앱 데이터 폴더의 `tools/ffmpeg` (시스템 PATH는 변경하지 않음)
- **검증**: 내려받은 파일은 SHA-256으로 검증하며, 해시가 맞지 않거나 취소하면 파일을 남기지 않습니다
- 진행률이 표시되고, 도중에 **내려받기 취소**를 할 수 있습니다
- 설치 후에도 libx264 검증에 실패하면 "설치했지만 검증 실패"로 표시됩니다

FFmpeg는 GPL 빌드이므로 라이선스 고지(`NOTICE.md`)를 함께 확인하세요.

## 3. 워크스페이스 의존성 설치 동의

새 워크스페이스를 만들 때(또는 v1 프로젝트를 가져올 때) 의존성 설치 동의를 묻습니다. 설치 실패는 워크스페이스 생성을 되돌리지 않으며, 폴더에서 `pnpm install`을 다시 실행하면 됩니다.

- 실행되는 명령은 고정되어 있습니다(임의 명령 입력 불가).
- 패키지를 인터넷에서 내려받으며, 패키지의 설치 스크립트가 실행될 수 있으므로 **신뢰하는 폴더에서만 동의**하세요.
- 진행 중에는 취소할 수 있고, 실패하면 종료 코드와 오류가 표시됩니다.

## 4. 다시 점검

- **다시 점검** 버튼으로 언제든 재검사할 수 있습니다. 마지막 점검 소요 시간(ms)이 표시됩니다.
- 최소 PATH 환경에서 실행하면 누락 항목마다 해결 방법이 표시됩니다.
